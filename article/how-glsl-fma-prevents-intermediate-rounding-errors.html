How GLSL FMA Prevents Intermediate Rounding Errors

In GLSL, precision loss during complex mathematical operations can produce visible rendering artifacts, numerical drift, and stability issues. The Fused Multiply-Add instruction, accessed via the fma() built-in function, mitigates these problems by computing the product of two values and adding a third in a single step with only one final rounding stage. This article explains how intermediate rounding occurs in standard floating-point operations, how the fma instruction bypasses this error vector, and where its application is critical in GPU shader programming.

The Mechanics of Intermediate Rounding

In standard IEEE 754 floating-point arithmetic, evaluating an expression like (a * b) + c requires two distinct operations:

  1. Multiplication: The GPU multiplies a and b, producing an intermediate result that is immediately rounded to fit the target precision (such as 32-bit float).
  2. Addition: The GPU adds the rounded intermediate result to c, followed by a second rounding step to store the final output.

Because the intermediate product is truncated or rounded before the addition takes place, low-order bits containing significant numerical data are permanently discarded. In iterative or sensitive algorithms, this compounding truncation can cause catastrophic cancellation, where subtracting two nearly equal numbers causes the most significant digits to cancel out, leaving only the accumulated rounding noise.

How the FMA Instruction Eliminates Rounding Loss

The fma(a, b, c) function computes (a * b) + c as an atomic operation. Internally, the hardware calculates the product a * b with infinite (or double-width) precision and holds this full representation in an internal register. The term c is then added directly to this unrounded product.

Only after the addition is complete does the hardware perform a single rounding operation to fit the result back into the standard floating-point format. By eliminating the intermediate rounding step, fma achieves higher numerical precision than executing an explicit mul instruction followed by an add instruction.

Critical Use Cases in Shader Math

Utilizing fma is essential in graphics programming scenarios that are sensitive to floating-point drift:

  • Polynomial Evaluations: Algorithms utilizing Horner's method for computing curves, splines, or transcendental approximations rely heavily on repeated multiply-add sequences. Unfused operations cause rapid error accumulation across successive terms.
  • Ray Tracing and Intersection Tests: Calculating ray-plane or ray-sphere intersections involves small discriminants. Rounding errors at intermediate stages can cause self-intersection artifacts (acne) or missed geometry.
  • Large-World Coordinate Systems: When rendering scenes with large spatial offsets, subtracting camera positions from world positions can cause vertex jitter. fma maintains precision when transforming high-magnitude coordinates.
  • Matrix Transformations and Dot Products: Accumulating matrix transforms using fused operations prevents subtle rotational and scaling drift over chained transformations.

Hardware Performance and the precise Qualifier

Beyond precision, fma is computationally efficient. Modern GPU architectures contain dedicated hardware FMA units in their execution cores, enabling the combined multiply-add operation to execute in a single clock cycle—matching or exceeding the execution speed of separate instructions.

To ensure consistent behavior, GLSL also provides the precise keyword. By default, optimizing compilers may automatically fuse or rearrange floating-point instructions to improve performance, which can lead to non-deterministic rounding behavior across different GPU vendors. Declaring a variable with precise forces the compiler to evaluate expressions strictly as written, ensuring that explicitly declared fma calculations are preserved without arbitrary reassociation.
