GLSL Const Expression Rules for Array Sizing

In the OpenGL Shading Language (GLSL), fixed-size arrays require their boundaries to be determinable during compilation to allow the graphics pipeline to allocate memory predictably. This article examines how GLSL's constant expression evaluation rules enforce compile-time array sizing, the criteria defining a valid constant expression, the compiler mechanics behind static resolution, and why this constraint is fundamental to GPU architectures.

The Requirement for Static Array Boundaries

Unlike general-purpose CPU languages that support runtime variable-length stack allocations, GLSL requires fixed-size array boundaries to be known before shader execution. Array declarations such as float data[size]; depend on size being an integral constant expression. This rule ensures that the shader compiler can determine exact register requirements, local storage allocations, and memory layouts prior to generating machine code for the target GPU.

Definition of a Constant Expression in GLSL

The GLSL specification defines a constant expression as an expression that evaluates to a constant scalar or vector at compile time. To qualify as a valid array size, the expression must evaluate to an integer greater than zero and be composed strictly of:

  • Literal values: Integer literals such as 4, 16, or 0x20.
  • Const-qualified variables: Explicitly defined variables using the const storage qualifier that are themselves initialized with constant expressions (e.g., const int SIZE = 8;).
  • Constant operations: Arithmetic, bitwise, or logical operators applied exclusively to other constant expressions (e.g., SIZE * 2 + 1).
  • Built-in functions: Certain deterministic built-in functions evaluated with constant parameters, allowing mathematical expressions like int(pow(2.0, 4.0)) to be computed at compile time.
  • Constructors: Array, vector, or matrix constructors composed exclusively of constant expressions.

Any expression depending on non-constant values—such as uniform, in (varying/attribute), or standard mutable local variables—violates these rules and cannot be used to size a fixed array.

Compiler Enforcement Through Constant Folding

The enforcement mechanism occurs during the semantic analysis and abstract syntax tree (AST) construction phases of the GLSL compiler. When the parser encounters an array declaration:

  1. AST Validation: The compiler traverses the sub-tree representing the array dimension.
  2. Attribute Verification: It checks every node within the dimension sub-tree. If a node references an identifier without the const qualifier, or an operation that depends on dynamic state, the node is flagged as non-constant.
  3. Constant Folding: If all nodes conform to the constant expression rules, the compiler applies constant folding, reducing the complex expression tree down to a single scalar integer.
  4. Boundary Validation: The resulting integer is verified to be strictly greater than zero. If the evaluation encounters a non-constant node or yields a non-positive integer, compilation halts immediately with a fatal error, such as "array size must be a constant expression."

Hardware and Architectural Rationale

GPUs achieve high throughput by scheduling thousands of threads across wide execution units (SIMD/SIMT). Dynamic stack allocation disrupts this model because the driver must pre-allocate private memory, register files, and thread stack space before launching thread groups.

By enforcing strict constant expression evaluation for array boundaries, the GLSL compiler can:

  • Map array elements directly to physical registers, maximizing access speed.
  • Prevent register spillage into slower local device memory.
  • Unroll loops containing indexed array accesses where indices are also constant.
  • Generate deterministic memory layouts required by uniform buffer objects (UBOs) and shader storage blocks.

While modern GLSL supports runtime-sized arrays at the tail end of Shader Storage Buffer Objects (SSBOs), standard local, global, and uniform arrays remain strictly governed by constant expression evaluation to maintain execution efficiency on GPU hardware.
