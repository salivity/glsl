Shader Binding Tables in GLSL Ray Tracing Explained

This article provides an overview of the Shader Binding Table (SBT) and shader records in hardware-accelerated GLSL and Vulkan ray tracing pipelines. It explores their architectural purpose, explaining how they connect 3D scene geometry to specialized execution shaders and per-object resources. Readers will gain a clear understanding of how these structures solve the dynamic dispatch challenges inherent to ray tracing, facilitating real-time rendering of complex scenes with diverse materials.

The Core Problem in Ray Tracing

In traditional rasterization pipelines, the CPU explicitly binds a shader program, sets uniforms, and issues a draw call for each batch of geometry. Ray tracing operates fundamentally differently: a single ray cast from the camera can bounce through a scene and intersect any arbitrary object. Because the CPU cannot predict which surface a ray will hit at runtime, the GPU must autonomously determine which shader to execute and which material data to read upon intersection. The Shader Binding Table (SBT) provides the mechanism to resolve this dynamic dispatch directly on the hardware.

What Is a Shader Record?

A shader record is a discrete block of memory residing within a buffer on the GPU. Each record consists of two primary components:

  1. Shader Identifier: A small, opaque handle provided by the driver that uniquely references a specific shader compiled into the ray tracing pipeline (such as a closest-hit, miss, or intersection shader).
  2. Local Root Arguments (Parameters): Optional user-defined data stored immediately after the identifier. This can include push constants, buffer device addresses, or direct descriptor references that provide material parameters, texture indices, or vertex attributes unique to that specific shader or geometry.

By packing both execution instructions (the identifier) and local state (the data) together, a shader record acts as a self-contained execution package for a single ray-geometry interaction.

What Is the Shader Binding Table (SBT)?

The Shader Binding Table is a standard GPU memory buffer containing an array of shader records. The SBT is logically organized into distinct regions mapped to different stages of the ray tracing pipeline:

  • Ray Generation Region: Contains the record for the ray generation shader, which initiates the tracing process.
  • Miss Region: Holds records for miss shaders executed when a ray fails to intersect any geometry (for example, environment map lookups or skyboxes). Multiple miss records can exist for different ray types, such as primary visibility rays versus shadow rays.
  • Hit Group Region: The largest section of the table, holding records for closest-hit, any-hit, and intersection shaders. These are tied to specific combinations of geometry instances and ray types.
  • Callable Region: Stores records for execution-on-demand shaders invoked directly from other shaders via dynamic branching.

How the GPU Indexes the SBT

During pipeline execution, the GPU calculates an offset into the SBT to locate the correct shader record using hardware-level indexing math. For hit shaders, this indexing combines several factors:

  • The instance-level SBT offset defined in the top-level acceleration structure (TLAS).
  • The geometry index inside the bottom-level acceleration structure (BLAS).
  • The ray contribution and multiplier passed to the traceRayEXT function in GLSL.

This calculation enables the hardware to automatically execute the correct material logic—such as evaluating a glass shader for transparent objects or a Cook-Torrance model for metals—without CPU intervention.

Summary of Purpose

The primary purpose of shader record buffers and the Shader Binding Table is to eliminate CPU overhead by providing a deterministic, hardware-friendly lookup system for ray-driven shader dispatch. They allow developers to map massive arrays of varying geometry and material properties to a single, monolithic ray tracing pipeline state object, enabling scalable and high-performance real-time rendering.
